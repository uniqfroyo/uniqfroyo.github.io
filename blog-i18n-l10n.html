Internationalization (i18n) and Localization (l10n) of UI Design

Designing for multiple languages changes how an interface wraps, aligns, and presents information.

Internationalization (i18n) prepares a product for use across languages and regions. Localization (l10n) adapts it to a particular locale. Translation is one part of that work. Teams might distribute language packs in desktop software, serve localized pages on the web, or let users choose a language in a mobile app. The implementation depends on the product and how it is distributed.

Typography depends on the language and the typeface

Replacing strings can expose assumptions about punctuation, alignment, and line height. Many Chinese characters are designed around a square, while Latin letters and words vary in width. The same font size can look different across scripts and typefaces, so compare them in the interface and adjust size or line height where needed. Check for clipping, especially where marks extend above or below the letters.

For longer passages, align text to the start of the line so readers have a consistent place to resume. Centering can work for a short headline. Preview the actual translation and check how it wraps, including the spacing around full-width punctuation.

Give translated text room to grow

A layout that fits the source language may break when a translation is longer or wraps at different points. Plan for that from the start:

  • Allow labels to wrap and containers to grow vertically. Check line height with the actual fonts and scripts.
  • Use a single column where long or editable text would be difficult to read in narrow columns.
  • Test grids with real translations. If labels wrap awkwardly, try fewer, wider columns.
  • Check line breaks by language. English usually wraps between words, while Japanese can wrap between characters, with restrictions on where certain punctuation may appear.
  • Give the text more space or reflow the layout before truncating it. Use an ellipsis only if the visible text still makes sense and readers can access the full text.

What else changes by locale?

Consider date and time formats, time zones, currencies, units of measurement, and the order in which names are written. Check font licenses for the markets and platforms where the product will ship, and account for local rules on what the product can collect or display.

A checklist for shipping a multilingual interface

  1. Extract titles, labels, button text, dialogs, and validation messages into source-language resources.
  2. Add the translations, switch languages in the product, and check both the new locale and the source locale.
  3. Test long content at narrow widths. Let rows grow to fit and make sure overflow remains accessible.
  4. Review typography in each script and prepare localized versions of graphics that contain text.
  5. Test with browser translation where relevant. Prioritize keeping content readable and controls usable when the text length or script changes unexpectedly.
